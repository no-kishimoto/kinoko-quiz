- 仕様バージョン: v1.0

## 1. この文書の目的

きのこ教育ゲームを再構築する際の確定仕様を管理する。

確定していない内容は実装者の判断で補完しない。各項目を順番に確認し、合意後にこの文書の「確定仕様」へ追加する。

## 2. Phase 0-1 確定仕様

### 2.1 タイトル画面

タイトル画面には、ゲーム名として「きのこクイズ」を表示する。

タイトル画面には次の3つの入口を設ける。

1. 「クイズで あそぶ」
2. 「きのこ さがし」
3. 「きのこ ずかん を みる」

表記は上記のとおりとする。

### 2.2 クイズの問題数

クイズを始める際、次のいずれかを選択できる。

- 5もん
- 10もん

### 2.3 きのこ図鑑の一覧

- 1ページに表示するきのこは3つとする。
- 配置は3列×1段とする。
- 総ページ数は、登録されているきのこの数から自動計算する。

## 3. Phase 0-2 確定仕様

### 3.1 対象ユーザー

- 4〜5歳の子どもを主な対象とする。
- ユーザーの息子が遊ぶことを想定して設計する。

### 3.2 対応端末

- 初期版はPCに対応する。
- スマートフォンおよびタブレットへの対応は、現時点では未確定とする。

## 4. Phase 0-3 確定仕様

### 4.1 出題形式

- 回答前は、きのこのシルエット画像を問題として表示する。
- 回答前のシルエット画像では、きのこごとに指定した1か所を円形に抜き、その範囲だけをカラーで表示する。
- 円形にカラー表示する位置は、そのきのこを見分ける手掛かりとなる部分に設定する。
- 表示された画像のきのこの名前を、3つの選択肢から選ぶ形式とする。
- 回答後は、シルエット画像を同じきのこのカラー画像へ切り替える。

### 4.2 ヒント

各問題では、次の情報をヒントとして提供する。

- 有毒または無毒
- 形態的特徴を表す短い一言

ヒントは問題画面に最初から表示する。ヒントを表示するための追加操作は必要としない。

## 5. Phase 0-4 確定仕様

### 5.1 回答後の表示

ユーザーが選択肢を選んだ後、次の内容を表示する。

- 回答が正解か不正解かの判定
- 正しいきのこの名前
- そのきのこについての解説

正誤判定は、大きな文字で次のように表示する。

- 正解時: 「せいかい！」
- 不正解時: 「せいかいは ○○」

不正解時の `○○` には、正しいきのこの名前を入れる。

解説には、次の3項目を掲載する。

- どこに生えるか
- 見た目の特徴
- 有毒／無毒と注意点

各項目は、4〜5歳の子どもが理解しやすい短い言葉で表現する。

ゲーム全体に共通する独立した安全注意書きは表示しない。各きのこの注意点は、上記の「有毒／無毒と注意点」に含める。

### 5.2 次の問題への進み方

- 回答後に「つぎへ」ボタンを表示する。
- ユーザーが「つぎへ」ボタンを押すと、次の問題へ進む。
- 回答後、次の問題へ自動では移動しない。

### 5.3 出題順と重複

- クイズを開始するたびに、登録されているきのこから問題をランダムに選ぶ。
- 1回のクイズ内では、同じきのこを重複して出題しない。

### 5.4 進行状況の表示

- 問題画面には、現在の問題番号と全問題数を表示する。
- 表示例は「もんだい 2 / 5」とする。
- 最終的な文字の大きさ、色、配置は現時点では未確定とする。
- クイズ中には正解数を表示しない。正解数は、すべての問題が終わった後の結果画面だけに表示する。

## 6. Phase 0-5 確定仕様

### 6.1 結果画面

すべての問題への回答が終わった後、結果画面を表示する。

結果画面には、次の内容を表示する。

- 全問題数
- 正解数

全問正解した場合は、次の特別メッセージを表示する。

> これで きみも きのこ はかせだ！！

正答率は表示しない。全問正解時を除き、正解数に応じた評価や特別メッセージは表示しない。

### 6.2 結果画面の操作

- 結果画面には「タイトルへ もどる」ボタンを表示する。
- ボタンを押すとタイトル画面へ戻る。
- 「もういちど あそぶ」ボタンは設けない。

## 7. Phase 0-6 確定仕様

### 7.1 図鑑一覧から詳細画面への移動

- 図鑑一覧に表示されたきのこをクリックできるようにする。
- きのこをクリックすると、選択したきのこの詳細画面を開く。

### 7.2 詳細画面の掲載情報

図鑑の詳細画面には、次の情報を掲載する。

- きのこの名前
- カラー画像
- 生える場所
- 生える季節
- 大きさ
- 色
- 傘・ひだ・柄などの特徴
- 有毒／無毒
- 似ているきのこ
- 食べ方（食用のきのこの場合）
- 豆知識

文章は、4〜5歳の子どもにも分かりやすい表現を基本とする。

### 7.3 詳細画面の操作

- 詳細画面には「ずかんへ もどる」ボタンを表示する。
- ボタンを押すと、その詳細画面を開く前に表示していた図鑑一覧ページへ戻る。

### 7.4 図鑑一覧のページ移動

- 図鑑一覧に「まえへ」ボタンを表示する。
- 図鑑一覧に「つぎへ」ボタンを表示する。
- 各ボタンを押すと、前または次の一覧ページへ移動する。
- 先頭ページでは「まえへ」ボタンを押せない状態で表示する。
- 最終ページでは「つぎへ」ボタンを押せない状態で表示する。
- 図鑑一覧には、現在のページ番号と総ページ数を表示する。
- 表示例は「1 / 4」とする。
- 総ページ数は、登録されているきのこの数から自動計算する。

### 7.5 タイトル画面へ戻る操作

- 図鑑一覧には「タイトルへ もどる」ボタンを表示する。
- ボタンを押すとタイトル画面へ戻る。

## 9. Phase 0-8 確定仕様

### 9.1 初期収録するきのこ

初期版には、次の15種類を収録する。

1. つちぐり
2. ほこりたけ
3. たまごたけ
4. そらいろたけ
5. はなほうきたけ
6. ほうきたけ
7. せみたけ
8. くりたけ
9. ちちたけ
10. きのぼりいぐち
11. おおきつねたけ
12. さるのこしかけ
13. まっしゅるーむ
14. かえんたけ
15. わかくさたけ

- 上記15種類に、しいたけ、ぶなしめじ、えのきたけ、まいたけ、えりんぎ、なめこの6種類を追加する。
- さらに、べにてんぐたけ、どくつるたけ、つきよたけ、らっぱたけ、まつたけ、ひらたけ、きくらげ、あみがさたけ、すっぽんたけを追加し、合計30種類とする。
- 30種類から、5問または10問を重複なしで出題できるようにする。
- 各きのこの毒性や図鑑情報は、データ層の作成時に信頼できる資料で確認する。

## 10. Phase 0-9 確定仕様

### 10.1 成績とプレイ履歴

- 初期版では、過去の成績やプレイ履歴を保存しない。
- クイズを開始するたびに、新しいクイズとして扱う。

## 11. Phase 0-10 確定仕様

### 11.1 ゲーム画面で使用する文字

- ゲーム画面内の文章、きのこの名前、ボタンおよびラベルには、ひらがなとカタカナを使用する。
- ゲーム画面内では漢字を一切使用しない。
- 本仕様書やソースコードなど、ユーザーに表示しない開発資料はこの制限の対象外とする。
- ゲーム画面では算用数字と記号を使用できる。
- 問題数やページ番号には、`5もん` や `2 / 5` のような表記を使用できる。

### 11.2 文字と操作ボタン

- 4〜5歳の子どもが見やすい大きな文字を使用する。
- 4〜5歳の子どもがPCで操作しやすい大きなボタンを使用する。
- 誤操作を減らすため、ボタン同士の間隔を広く取る。
- 具体的な文字サイズ、ボタンサイズおよび間隔は、UI設計時に決定する。

### 11.3 配色

- 4〜5歳の子どもが親しみやすい、明るく楽しい配色にする。
- 具体的な色や配色ルールは、UI設計時に決定する。

## 12. Phase 0-11 確定仕様: きのこ探し

- タイトル画面に「きのこ さがし」の入口を設ける。
- 森の背景のなかに、3種類のきのこをかくして表示する。
- きのこ探しの問題は15種類用意する。
- 開始するたびに、15種類の問題から1問をランダムに表示する。
- 問題ごとに、探すきのこの組み合わせと隠れる場所を変える。
- 背景をクリックしてきのこを見つける形式とする。
- 見つけたきのこには丸いしるしを表示する。
- 3種類すべてを見つけたら「きのこ さがし だいせいこう！」と表示する。
- 「タイトルへ もどる」ボタンでタイトル画面へ戻れるようにする。

### Phase 1 リポジトリ設定

- ブランチ運用: 初期版では `main` ブランチのみを使用する
- コミット方針: 各Phaseの完了時にコミットする

### Phase 1 技術構成

- プログラミング言語: Python
- UI: Gradio Blocks
- 画像加工: Pillow
- テスト: pytest
- PCでローカル起動できる構成にする。
- Google ColabからGradioの共有リンクを使って起動できる構成にする。
- きのこデータの保存形式は、データ層の工程で決定する。

### Phase 1 完了状況

- リポジトリ名、公開範囲、ブランチ運用: 完了
- ローカルリポジトリの構成作成: 完了
- `main` ブランチでのGit初期化: 完了

### Phase 2 データ層の方針

- きのこの情報はJSONファイルに保存する。
- Python側でJSONを読み込み、ゲーム内で使用できるデータへ変換する。
- Python側で必須項目、データ型、識別キーの重複および対応素材を検証する。
- 新しいきのこは、JSONのデータと対応する画像を追加することで収録できる構成にする。
- JSONの具体的な項目は、Phase 2で順番に確定する。
- 円形カラー表示には、きのこごとの対象部位と、実画像に対する横位置・縦位置・半径を保存する。
- 画像登録前は円の位置を空欄にできるが、ゲームで使用する前の素材検証では位置を必須とする。
- 食毒が確認できない種類は、推測で有毒・無毒に分類せず「どくが あるか わかっていない」と表示する。
